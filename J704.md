# J704 / M5 development snapshot

The default branch remains `integration/aurora`. This fork starts from the
hardware-tested Aurora commit `311471f73e9919764bfb24acfe7eeb7c5230795a`,
rather than moving to a newer upstream revision during publication.
Target: Mac17,2 / J704AP / T8142 / G17G C0. The tested machine has 32 GB and ten GPU cores.

## Included changes

- Asahi HAL300 GPU support, firmware channels, compute/render commands,
  memory management, recovery and desktop latency fixes (phase2n80 source).
- Internal DCP v27i swap/link handling and the independently tested external
  DCP E37 path, including HDMI/USB-C routing and reconnection.
- T8142 PMP boot arguments/report layout, J704 memory/fabric performance
  floors, uncached GPIO support and DisplayPort crossbar control.
- T8142 ATC PHY/DP support and bounded SN201202x wake retries.
- Hibiscus AVD support, including the larger H.264 motion-vector allocation.
- T8142 broken-SEIS workaround and software-backed KVM guest timers, keeping
  the existing direct timer path on other hosts.

## Build integration

Use the upstream ARM64 Rust/LLVM build requirements. The validated kernel
configuration uses 16 KiB host pages and builds Asahi, PMP, display, ATC PHY
and the Type-C controller as modules. Enable `CONFIG_DRM_ASAHI_G16` for the
HAL300 builder. The added optional modules have these configuration symbols:

| Symbol | Module |
| --- | --- |
| `CONFIG_DRM_APPLE_J704_EXT` | `appledrmext` (requires `CONFIG_DRM_APPLE=m`) |
| `CONFIG_MUX_J704_DPXBAR` | `j704_dpxbar` |
| `CONFIG_PINCTRL_J704_GPIO` | `j704_gpio_pinctrl` |
| `CONFIG_APPLE_J704_PMP_REPORT` | `j704_pmp_report` |
| `CONFIG_APPLE_J704_MEMPERF` | `j704_memperf` |

`drivers/gpu/drm/apple/j704-ext/` preserves the E37 external driver while
the normal directory retains v27i internal display fixes. Files identical
between them are relative symlinks; differing sources/headers are separate.
The `ext-*.c` translation units select the external symbol namespace.
This is temporary packaging of independently validated implementations,
not a completed upstream unification. Keep internal and external modules
built from the same checkout.

## Firmware and device tree

Use a matching [Aura](https://github.com/dmitzsaz/aura) /
[U-Boot](https://github.com/dmitzsaz/u-boot) handoff with the board's current
firmware reservations, power/memory topology and device descriptions.
The GPU uses macOS 27 HAL300 firmware and per-machine DT power inputs
(`apple,hal300-derived`). The public builder includes layout, relocations,
SoC register windows and host policy; calibration values must come from
that machine. The captured-graph loading path has been removed: startup always builds the
HAL300 graph from the public layout and the supplied inputs.
A driver build alone cannot replace this boot-time handoff.

Build `apple/avd-fw-v5-t2.bin` from the open-source
[avd-fw fork](https://github.com/dmitzsaz/avd-fw) for video decode.
Use the companion [Mesa fork](https://github.com/dmitzsaz/mesa), based on
`c208afc352e9d4c10ee71c883a369a9079dd7d84`, for the tested GPU userspace.

Raw ADTs, Apple firmware, calibration, captured initdata graphs, machine
identifiers, boot-specific DTBs, keys and RAM dumps are not distributed.

## Validation and limits

The underlying sources were built against the Aurora `7.3.0-1-2-ARCH` SDK
and exercised on J704. GPU checks included Vulkan compute/render/image/query
workloads, Zink/OpenGL desktop use and fault recovery. The release Mesa
stack ran Hyprland, Firefox and Telegram. This is not a conformance claim.

Internal display and external HDMI/USB-C replug/routing were exercised;
E37 restores HDMI after a USB-C display disconnects. Only one external
pipeline is qualified. HDMI audio and a second external display are open.
Memory-floor control passed three lid-close suspend/resume cycles; its
long-term battery impact remains unmeasured.

AVD output matched FFmpeg for tested H.264, HEVC 8/10-bit, VP9 and AV1 clips.
KVM checks covered guest sleeps, timerfd/epoll/sockets, all four muvm vCPUs,
FEX sleep and actual guest GPU work. Existing KVM timer selftests also passed
under a separate emulated EL2 host. `kvm-arm.force_sw_timers=1` selects the
fallback for testing on another VHE+ECV host; nested guests are rejected
while it is active. Timer/counter trapping adds overhead.

A complete kernel and Mesa from the earlier fork source trees were installed
on J704 as `7.3.0-j7041` and Mesa 26.3 development. Accelerated Vulkan/OpenGL,
120 Hz internal display, guest timers and desktop use passed. After restoring
the J704 SMC AFE reset producer, the user confirmed trackpad motion and clicks.
The subsequent boot with the corrected initramfs has not yet been observed.
Audio, microphones, camera, internal NVMe and Touch ID remain unestablished.

## Ordinary board and driver integration

`arch/arm64/boot/dts/apple/t8142-j704.dts` is the board description. It includes
`t8142-j704-platform.dtsi` for the PCIe, radio, SD and keyboard-light resources.
The U-Boot companion carries the same two source files. They contain static
hardware topology, with empty memory/OPP reservations and disabled engines
that require a loader handoff. They contain no owner MAC addresses, calibration
blobs, HAL300 coefficients, or physical addresses of firmware allocations.

The matching Aura loader fills the current machine's memory, CPU/GPU OPPs,
PCIe tunables, radio identity/calibration, and GPU/display/PMP handoff data.
The owner supplies HAL300 values as a private overlay before Aura prepares the
DT. Aura validates the profile's source frequencies, voltages and sample period
against this boot's ADT. Automatic acquisition or derivation of that profile
is outside this integration. A profile for one machine is not a generic default.

Use U-Boot's inherited, prepared DT for Linux. Loading the raw static DT again
from an extlinux `FDT`/`FDTDIR` entry discards the loader's memory and firmware
fixups. The static DTB is a loader input, not a replacement for a live DTB.

`CONFIG_APPLE_J704_PLATFORM` links one OF platform driver. It waits for SMC,
validates all twelve loader tables before hardware access, performs ordered
PCIe power/PHY/link startup, then publishes the dormant DART and PCI host
nodes. Errors stop the sequence and partial state remains pinned until reboot.
It replaces separately loaded one-shot stage modules. The common Apple PCI
host driver handles the T8142 RID/SID layout and both root ports. The regular
macsmc drivers provide read-only battery telemetry and the J704 trackpad reset
producer. Keyboard lighting is described by DT resources.

`arch/arm64/configs/j704_defconfig` is the reference configuration. SMC, its GPIO
provider, the RTKit helper and PCIe coordinator are built in, so early SD/root
startup does not depend on a private initramfs module-loading sequence.
Use a normal distro initramfs with the complete matching module tree and
required private firmware. Build/package recipes remain outside this fork.

## Integration verification

The earlier driver stack was exercised on the hardware as described above.
The newly consolidated boot chain has not yet been cold-booted as a complete
replacement. Aura's PCIe/CPU producer, GPU producer and inherited DART view
pass host tests with ASan/UBSan. The GPU producer's ten generated reservations
match the working handoff using private local ADT/profile inputs. DT source
compilation and focused binding validation pass. The unified PCIe driver and
Asahi graph-only path compile and link against the matching ARM64 SDK.

These checks establish source/build integration, not a hardware acceptance
result for the new boot object. Audio and camera work is independent of this
publication. The running desktop and its device lifetimes are preserved.
